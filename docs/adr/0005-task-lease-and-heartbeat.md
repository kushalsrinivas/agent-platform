# ADR 0005: Task leases, heartbeat renewal and fencing tokens

- **Status:** Accepted
- **Date:** 2026-11-22
- **Deciders:** Architecture
- **Related:** [state-machines/task.md](../state-machines/task.md), [failure-and-recovery.md](../failure-and-recovery.md), [proto/worker/v1/worker.proto](../../proto/worker/v1/worker.proto)

## Context

A worker can crash, hang, lose the network, or be replaced while a task is running. The orchestrator needs to
recover the task without ever accepting a result from a process that no longer owns it. We need a mechanism that
works across process pauses, clock skew and broker redelivery, and that does not require a separate lock service.

A simple "worker says it is alive" heartbeat is insufficient: after a partition, the old worker may still believe
it owns the task and send a result. Recovery must be safe even if two processes both believe they own it.

## Decision

- Assignment is a **time-bounded lease** stored on the task row: `owner_worker_id`, `lease_id`, `lease_expires_at`.
- `lease_id` is a UUID generated by the orchestrator at assignment. It is the **fencing token**. Every accept,
  result, artifact request and credential fetch carries `(task_id, attempt_id, lease_id)`. Renewal only extends an
  unexpired lease; once expired, an attempt can never be revived by a late heartbeat.
- A result is accepted only if the task is `assigned`/`running`, the owner matches, the lease matches, the attempt
  is the current open attempt, and `lease_expires_at > now()`.
- Lease times use the **PostgreSQL clock**. Worker clocks never determine expiry or order.
- Timing defaults:
  - heartbeat every **5s**, sent on the worker control stream with active `(task, attempt, lease)` entries;
  - lease TTL **30s**, renewed implicitly by a matching heartbeat;
  - worker unhealthy after **15s** without heartbeat (no new assignments);
  - reaper tick **5s**, protected by a PostgreSQL advisory lock so only one replica reaps.
- A worker process restart changes its `boot_id`; the orchestrator closes all open attempts from the previous boot
  immediately as `lease_expired` (no waiting for TTL).
- The reaper closes expired attempts, sets `outcome_unknown`/`effect_uncertain` appropriately, and applies the retry
  policy. It never guesses a result.
- Fencing protects state, not the outside world: a partitioned worker may still perform side effects. That is
  covered by ADR 0006.

## Consequences

**Positive**

- Recovery is automatic and bounded (≤30s after the last heartbeat) without a lock service or leader election.
- Two workers can temporarily run the same task without both committing results.
- Worker clock skew and VM pauses do not extend ownership; a paused worker simply loses its lease.
- The same primitive works for rollout, drain and cancellation.

**Negative**

- A 30s TTL limits how long a lease can be held without a heartbeat; long-running tasks need renewal, which the
  control stream provides. Losing the stream mid-task will eventually reassign the task even if the sandbox is
  healthy.
- A paused worker can resume and produce a duplicate external effect before it learns it was fenced.
- Heartbeat/lease tuning is a trade-off between recovery latency and false reassignments. 30s is the Phase 1
  default; it is configuration, not a protocol constant.

## Alternatives considered

- **Redis locks with TTL.** Fast, but adds another authority and a split-brain failure mode; database fencing is
  simpler and already needed for state.
- **NATS ack-based ownership only.** Ack timeout is not a fencing token; a redelivery after a crash can be
  processed while the old process is still alive. Rejected as insufficient.
- **Worker self-fencing.** A worker cannot be trusted to declare itself dead; the orchestrator must decide.
- **No lease, rely on TCP disconnect.** Does not survive half-open connections or process pauses.
- **Very long TTL (hours).** Simpler for long tasks, but slow recovery and more duplicate execution.

## Verification

- Concurrent result tests: two workers, same attempt, only the lease owner commits.
- A reaper/result race test under two transactions yields exactly one winner.
- Lease expiry tests manipulate worker clocks and confirm no effect.
- Restart tests with a new `boot_id` close open attempts before redelivery is accepted.
- Heartbeat loss tests confirm no new assignments after 15s and reassignment after 30s.
